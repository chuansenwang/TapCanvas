# 教学视频分镜流水线契约（草案）

本文定义「英语教学脚本 → 资产 → 分镜脚本 → 分镜图 → H3 视频」链路中，
分镜脚本层与分镜图层之间的映射契约。本文是评审用设计文档，不是运行时输入来源；
运行时知识只允许来自 `skills/`、真实代码、项目状态、工具返回结果与用户显式上下文。

## 1. 要解决的问题

原链路把「拆镜头」与「画分镜」压在一个动作里，产生三个后果：

1. 下游 H3 需要逐段时长与台词归属，而这些事实只能来自分镜脚本层；中间只有一张多格分镜图时，时长与分段只能从图里重新推断。
2. 成图返修没有对照物，只能对着自己的提示词自检，无法判断「某镜头是否漏了」。
3. 角色卡、场景卡、配音卡都以镜头为单位挂载；分镜格是版面单位，资产挂在格上会立刻混乱。

因此本文把「拆镜头」与「出图」明确拆为相邻两层，并定义它们之间唯一允许的交接格式。

## 2. 核心决策：单元粒度

`tapcanvas-storyboard-expert` 的默认镜头数量规则按小说章节字数给出（≤1200 字为 6–8 镜头）。
该规则不适用于本链路：一集教学脚本是 700–1000 词、18–26 个对话回合、约 6–9 分钟的内容，
按默认镜头数会严重欠覆盖。

本链路采用 **教学节拍（beat）** 作为③④⑤三层共用的唯一单元：

```text
一个 beat ≈ 一次语义完整的发言，或一组紧密问答
```

依据：

- 教学脚本的承载物是台词，一个回合的台词必须完整落在同一单元里，才能逐字入图并保持说话者归属。
- A1–A2 语速偏慢，一个回合实测约 12–18 秒，正好落在 H3 单段 4–15 秒区间附近。
- `tapcanvas-storyboard-expert` 明确允许「若用户指定镜头数，以用户要求为准」，按 beat 定镜头数不违反其规则。

预期规模：一集 beat 数 ≈ 对话回合数 ≈ 18–26，即约 18–26 张分镜图；按每页 4–6 格计约 4–6 页。
这是教学视频体裁的合理体量，不是退化。

## 3. 三层单元与统一 ID

| 层 | 单元 | 载体 | 说明 |
| --- | --- | --- | --- |
| ③ 分镜脚本层 | beat | `storyboardScript` 节点（纯文本分镜脚本） | 由 `tapcanvas-storyboard-expert` 产出，含逐 beat 的镜头语言与时长 |
| ④ 分镜图层 | 分镜格 | `image` 节点（本地文生图产物） | 由 `img-storyboard-narrative` 产出提示词后生成 |
| ⑤ 视频层 | P 段 | H3 Ref2VA 提示词 | 由 `h3-storyboard-manga` 产出六字段正式提示词 |

三层共用同一个 beat 标识 `beatId`（形如 `BEAT_01`），格式与 `tapcanvas-storyboard-expert`
已有的 `SHOT_01` 编号习惯保持一致。任何一层缺失 `beatId` 即视为契约断裂。

映射关系：

- ③ → ④：默认 1:1；仅当该 beat 的动作无法用单一时间点表达时，才允许拆为多格，并在格上标注所属 `beatId`。
- ④ → ⑤：默认 1:1 或 1:N（多个相邻格合并进一个 P，需满足 `h3-storyboard-manga` 的合并条件）；仅在台词量超过 15 秒时才拆 P。
- 不允许反向推导：不得从④的分镜图反推⑤的台词或时长。

### 说话人数量（③层规划约定）

单个 P 建议不超过 **2 名**说话者。这是制作约定，不是模型硬限制。

事实依据：

- H3 的语音由提示词 `<d>` 内的台词文本生成，**视频不由参考音频驱动**。
- `<Audio N>` 的角色固定为 `reference`：只提供音色与表达方式，不复制信号、不参与画面生成。
- 因此「说话人数量」与「参考音数量」是两类量，不能互相换算。

保留 ≤2 的实际理由：教学对白的剪辑与理解清晰度，以及便于逐段核对；与参考音无关。

一集可以有任意多名说话者（Mike、Kate 及各单集配角）。

## 4. ③ → ④ 字段映射

`img-storyboard-narrative` 的输出契约要求一条提示词按六段组织。映射如下：

| ④ 提示词段落 | 来源字段 |
| --- | --- |
| 1 任务与风格 | `globalStyle`（genre / visualTone / palette）+ 用户选定的动漫画风或现实世界模式 |
| 2 版式 | 由本页包含的 beat 数派生；阅读顺序、格数、行列由生成方决定并写具体 |
| 3 参考与全局状态 | `cast[].anchorTraits` + 角色卡/场景卡真实资产 + `scene` + `continuityLocks` |
| 4 逐格瞬间 | 逐 beat 的 `actionChain` + `composition` + `performance` + `camera` |
| 5 视觉层级与相关防错 | `negativeConstraints` + `failureRisks` + `continuity.forbiddenDrifts` |
| 6 文字策略 | `script.md` 中该 beat 的逐字台词原文 + 说话者名 + 文字类型 |

硬性约束：

- ④ 不得输出视频时间码、连续运镜或配音参数；`durationSec` 只留在③与⑤，不进入④。
- ④ 的台词只能来自 `script.md` 原文，不得改写、概括、翻译或增删。
- 角色以 `@角色名` 绑定角色卡，场景以场景卡锚点绑定；缺少真实资产 URL 时显式失败，不回退为文字描述冒充。

## 5. ④ → ⑤ 字段映射

H3 只接受两类事实输入，二者缺一不可：

| H3 需要的事实 | 唯一来源 |
| --- | --- |
| 画面、构图、镜头顺序、人物与场景外观 | ④ 生成的真实分镜图（作为 `Picture N`） |
| 台词原文、说话者、语言标签、时长 | ③ 的剧本事实（`<d>` 内容 + `durationSec`）+ `script.md` |

约束：

- 台词事实源是 `script.md`，不是分镜图中的文字。禁止从图里读台词。
- ④ 默认应输出**无字版**分镜图。含可读文字的参考图会被 H3 强制降级为 `partially_preserved`，并引入伪文字风险。
- 时长以 H3 自己的口播估算规则重算，不使用③的 `durationSec` 原值；单个 beat 超过 15 秒时必须拆 P，并说明拆分依据。
- 同一角色的音色锚点由配音卡（`voice_card` + `voiceCharacter`）提供。参考音频只锁音色、不驱动画面，具体见第 7 节。

## 6. 必须守恒的不变量

跨层传递时以下事实不得丢失或改写：

1. `beatId` 与事件先后顺序。
2. 每个 beat 的逐字台词原文、说话者归属、语言。
3. 人物关系与身份（角色卡锚点）。
4. 场景地理与地标、道具归属。
5. 信息揭示顺序：不得把应当后续揭示的内容提前写进较早的格。

## 7. 已知冲突与处理方式

| 冲突 | 说明 | 处理 |
| --- | --- | --- |
| 时长哲学不一致 | ③ 的模板按 15 秒 Seedance 片段设计；⑤ 按台词容量算最短可行时长，且明确「没有默认档位」 | 以⑤重算为准，③的时长仅作估算 |
| 参考音频的作用与上限 | H3 Ref2VA 的 `<Audio N>` 是 `reference`：**只提供音色与表达方式，不驱动画面**，语音由 `<d>` 台词文本生成。上限为 3 条、每条 2–15 秒、总时长不超过 15 秒，且音频不能作为唯一参考输入 | 需要跨镜锁定音色的角色使用配音卡作为参考音；超过 3 名需要锁音色的角色时，其余角色改用文生音色描述。该约束**不限制说话人数量**，也不构成拆 P 的理由 |
| 单 beat 超 15 秒 | 语速慢的长回合可能超过 H3 单段上限 | 显式拆 P 并说明依据，或精简单段台词 |
| 台词入图容量 | 长台词与「一格一个时间点」可能冲突 | 按 `img-storyboard-narrative` 的规则拆页，禁止删台词或缩到不可辨认 |
| 音频 UNET 可用性 | 配音卡锁音色依赖参考音执行；当前本地只注册了 `fl2va` 音频 UNET | 执行前对 `8188` 的 `/object_info` 实时枚举确认，不得假设存在 `ref2va` |

## 8. 失败规则

遵循显式失败与零隐式回退：

- 缺少真实资产 URL（角色卡、场景卡、配音卡）时显式失败，不生成文字占位资产。
- 缺少台词原文或说话者归属时显式失败，不猜测、不默认。
- 语义判断证据不足时显式失败，不使用本地默认 route、默认 prompt 或默认工作流兜底。
- 已成功产出的资产不得在后处理阶段被拦截、回滚或丢弃。

## 9. 本契约不覆盖的内容

- 不定义 `lesson-asset-extract` 的抽取规则（属资产层，另行定义）。
- 不定义技术选型（技能落哪个 skill 根、是否接入 `/public/chat`）。
- 不定义成片剪辑、BGM、字幕等后期环节。

## 10. 待确认项

1. ③ 的镜头数是否按 beat 数（18–26）而非字数规则确定。
2. ④ 是否统一采用无字版分镜图。
3. 配音卡音色锚点是否全角色预建（含单集配角），还是仅常驻双主角预建、配角按需生成。
4. ④ 的分镜图页数与格数是否有硬限制。
