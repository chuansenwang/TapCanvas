# AI 错误长期经验

本文件只记录高频、稳定或破坏性高，且值得长期防复发的错误模式。每条经验使用三行：`标题`、`来源`、`教训`，并与流水中的 `HE-FL-XXX` 关联。

## HE-FL-001 Skill 脚本用相对层级常数推断跨目录根路径

标题：Skill 脚本用相对层级常数推断跨目录根路径
来源：`docs/engineering/learning-extractor.md` 中三起已确认事件（`prepare_subtitles.py` 的 `parents[4]`、`prepare-youtube.mjs` 的 `../../../../..`、`film-style-replication/scripts/extract-mp4-frames.mjs` 的 `../../../../..`）
教训：skill 脚本要访问项目根、其他 skill 或运行时资产时，必须由真实存在的标记文件向上查找或由调用方显式传入，并支持环境变量覆盖；禁止用固定的 `../` 层数推断根目录。新增或改动后必须真实执行一次命令验证路径，发现定位失败要显式报错，不能继续执行到后续阶段的隐式错误。标记文件本身必须唯一：仓库里常有嵌套工作区（如 `apps/agents/`、`third-party/*`）携带同名标记，选标记前要先枚举全仓同名文件确认唯一，并核对解析结果确实等于期望根目录，不能只凭「命令没报错」或「向上找到了」就判定正确。

## HE-FL-002 把「未暴露 / 未接入」当成「能力不存在」直接回报缺口

标题：把「未暴露 / 未接入」当成「能力不存在」直接回报缺口
来源：`docs/engineering/learning-extractor.md` 中 `film_audio_gen` 事件（占位 `throw` 与 skill 文案互相印证，掩盖了早已存在的 `generateAudioToCanvas` 执行器）
教训：向用户报告「没有执行器 / 未接入 / 做不到」属于能力结论，必须先在运行时代码里核实证据：检索既有实现与真实调用点（谁在调用、输入输出契约是什么、是否已有等价工具或 API），确认不存在可复用实现后再报告。占位 `throw`、工具未暴露、skill 与文档表述都不构成事实证据；文档与运行时代码冲突时以代码为准，并在同一次改动里同步文档与 skill，避免错误结论继续被后续回合当作事实复用。

## HE-FL-003 用「看似等价」的数据源替代执行器真实数据源

标题：用「看似等价」的数据源替代执行器真实数据源
来源：`docs/engineering/learning-extractor.md` 中「video modelKey 契约不可满足」事件（首版目录工具接到只覆盖系统渠道的 new-api 运行时投影，实测 image/video/audio 三项全为 0）
教训：当契约要求「精确标识必须来自运行时目录」时，必须先确认该目录的数据源与执行器解析时使用的数据源是同一个，并用真实运行数据实测它在执行所在环境下非空；本地执行器目录与系统渠道运行时目录是两套来源，不能因为名称相近就互相替代。同时，若契约要求调用方提交「运行时目录返回的精确标识」，却没有任何工具或上下文能让调用方拿到该目录，这本身就是不可满足的契约，必须在实现侧补齐获取途径，而不是把失败归因于调用方填错。本类事件与 HE-FL-001（用固定层级常数推断根路径）同源：都是未用真实数据验证假设就推进实现。
