# 万物复刻

## 使命

把用户提供的视觉资产转成一份能执行、能追溯的复刻契约，再据此生成或编排目标产物。复刻不是笼统地“画得像”，而是明确保留什么、替换什么、哪些事实没有证据，防止主体、构图、材质、文字层级或镜头连续性在执行时漂移。

本技能适用于静态图、海报和版式、角色、产品、场景、道具、分镜以及视频片段。它只处理用户有权使用的资产；不要复现或保留水印、商标、受保护角色的可识别形象、原始台词或来源标识。用户需要相近的商业视觉效果时，保留可见设计语言，使用新的文字、名称和主体。

## 成功标准

一次合格的复刻必须满足以下条件：

- 每项视觉结论都能回溯到具体输入资产和区域，不把推测写成事实。
- 目标、参考、保留项、替换项、禁止项和交付规格均已明确；不存在“尽量像”这类不可执行要求。
- 每张参考图都有职责。参考图只约束它实际提供的身份、材质、空间、版式、色彩或动作，不以无关资产覆盖整个画面。
- 输出的关键不变量与用户意图一致：例如主体替换时保留目标构图，产品复刻时保留可见结构与材质，视频复刻时保留镜头节奏与连续性。
- 结果和元数据全部保留。生成成功后不以自动评分、视觉门禁、自动回滚或静默重生成为由丢弃产物。

## 触发边界

使用本技能处理“基于参考资产重做或替换”的任务。常见目标包括：

- 将目标图中的人、产品、道具、场景或角色替换为参考资产，同时保留原有画面设计。
- 根据多张参考图重建角色、产品、材质、场景或插画的稳定资产，并用于后续图片、分镜或视频。
- 复现广告、海报、包装、UI 画面、拼贴、九宫格或分镜的版式、信息层级和镜头顺序。
- 将一个画面的可见视觉语言迁移到新内容，但不复制原始主体、文案、标识或受保护形象。
- 让一段视频或多张分镜延续既定主体、空间、镜头和动作状态。

不要用于单纯的文生图、没有参考资产的风格探索、只需抠图/裁切的确定性编辑，或用户只要求分析而不需要复刻方案。只分析时，可以输出复刻契约，但不发起生成。

## 输入契约

先确认每个输入的角色，不从文件名猜测。使用下列角色；一个资产可承担多个角色，但要逐项说明：

- `target`：要被改造、续写或保留版式/镜头的目标图、目标视频或目标画布节点。
- `subject`：替换或重建的核心人物、产品、物件、角色或标志性主体参考。
- `style`：仅提供色彩、光影、材质、构图或渲染语言的参考。
- `layout`：仅提供版式、分格、信息层级、留白和文字区关系的参考。
- `scene`：提供空间结构、环境材质、时间或光源逻辑的参考。
- `motion`：提供镜头、运动、节奏、转场或动作边界的视频/分镜参考。
- `mp4`：用户直接上传的本地 MP4。它先经 FFmpeg 转为带时间码的 PNG 候选帧；候选帧经审查后才能分别承担 `style`、`scene`、`layout`、`subject`、`motion` 或 `context` 角色。MP4 文件本身不直接充当静态风格证据。
- `context`：补充叙事状态、道具状态、人物关系或连续性信息的参考。
- `mask`：明确局部编辑范围的结构性输入。

同时收集交付目标：产物类型、数量、画幅或尺寸、时长、目标渠道、是否保留文字区、需要替换的文字及用户明确的禁止项。用户没有提供必要事实时，报告缺少的资产或信息；不得编造主体特征、被遮挡结构、文字内容、镜头前后状态或参考图外的细节。

当输入为多张图时，先以视觉证据而不是文件名确定优先级。若目标图与参考图的比例、视角、光向、叙事状态或版式相互冲突，先呈现冲突和可选取舍，等待用户指定，或在用户已明确优先级时按其优先级执行。

### MP4 上传预处理

用户直接上传 MP4 且目标包含风格提取、静态视觉语言迁移、版式复刻或素材分析时，先执行 FFmpeg 到 PNG 的候选帧抽取。这里的“FFPNG”统一指 `FFmpeg -> PNG`，不假设存在另一个名为 FFPNG 的程序。

```bash
node apps/agents/.agents/skills/tapcanvas-film-style-replication/scripts/extract-mp4-frames.mjs \
  --input "<uploaded-mp4-local-path>" \
  --output-dir "<approved-runtime-output-dir>" \
  --format json
```

- 仅接受可读取的本地 `.mp4` 文件；路径、格式或 FFmpeg 不可用时原地失败并报告真实错误。
- 省略 `--output-dir` 时，默认写入 TapCanvas 仓库根的 `.runtime/film-style-replication/<视频名>-frames/`。仓库根按 `package.json` 的 `name: tapcanvas-workspace` 向上查找确定（可用 `TAPCANVAS_REPO_ROOT` 覆盖），不能靠相对层数推断。
- 脚本先检测场景变化，再仅在每个检测到的镜头转换候选处抽取对应 PNG；不会按固定秒数、固定帧率或等距时间间隔抽帧。`sceneTransitions[]`、`candidateFrames[].sourceTimeSec` 和本地 PNG 路径是可追溯证据。场景变化是候选镜头转换，不等同于最终镜头边界或全部视觉事实。
- 根据目标，从候选帧中选择能证明风格、构图、材质、光影或版式的帧，并记录每帧承担的输入角色、时间码和可见区域。不要仅挑一张最醒目的帧覆盖视频中互相矛盾的视觉状态。
- 抽帧成功后，才可将选中的 PNG 作为图片输入上传、绑定或交给视觉理解；真实 TapCanvas 媒体接口仍必须通过 `tapcanvas-api` 调用。原 MP4、全部候选 PNG 和抽帧 JSON 均保留，不覆盖已有结果。
- 若场景变化阈值下未检测到镜头转换，或候选帧无法支持用户要求的视觉结论，显式报告缺口。允许用户提供更低的 `--scene-threshold` 或补充静态参考，但不得自动按固定时间间隔补帧。

## 复刻契约

生成或修改前，先建立以下中文契约。它可以作为对用户的简要确认、画布节点元数据或 specialist 的输入；不需要为了形式再创建平行文本节点。

```markdown
## 复刻契约
- 目标：
- 输入资产与角色：
- 交付：
- 保留项：
- 替换项：
- 风格锚点：
- 空间/版式锚点：
- 连续性锚点：
- 文字与标识处理：
- 参考图职责：
- 禁止项：
- 已知缺口与冲突：
- 可验证证据：
```

“保留项”和“替换项”必须可观察且互不矛盾。将信息按以下层次组织：

1. 全局锚点：画幅、构图重心、镜头距离、布局网格、主色关系、主光方向、渲染媒介。
2. 身份锚点：人物脸部与发型、产品轮廓、物件结构、服装、材质、关键标识的可见替代方案。
3. 关系锚点：主体与环境比例、前中后景、人物位置、接触关系、遮挡、文字区与图像区。
4. 时序锚点：动作起止、道具状态、镜头方向、屏幕方向、前一镜尾帧与下一镜首帧的连续性。
5. 细节锚点：纹理、反光、颗粒、边缘、阴影、局部磨损和小型道具。

上层锚点与下层细节冲突时，以用户明确指定的优先级为准；未指定时，先请求决定，不擅自用视觉风格覆盖身份或可读性。

## 执行方式

### 1. 识别复刻模式

根据复刻契约选择最小必要模式，可组合，但不要为同一个目标建立两套彼此竞争的执行路径：

- **主体替换**：保留 `target` 的构图、镜头、空间、光影和版式，使用 `subject` 替换人物、产品或物件。
- **主体重建**：根据一个或多个 `subject` 参考，先建立可复用的角色、产品、场景或道具资产，再服务多个镜头或版面。
- **视觉语言迁移**：保留新内容的叙事和身份，仅继承 `style` 的可见色彩、材质、光影、构图或渲染规律。
- **版式复刻**：保留 `layout` 的信息层级、网格、分格、留白、对齐、文字区和阅读顺序，用新的内容填充；文字必须由用户明确提供或确认。
- **场景复现**：保留 `scene` 的空间拓扑、可见主光、材质关系和透视，将主体替换为目标内容。
- **镜头连续复刻**：保留 `motion` 的镜头规模、运动方向、动作因果、时长和转场意图，使用已确认角色和场景资产产出视频或连续分镜。

### 2. 提炼证据

逐资产记录可见事实。至少覆盖与当前模式有关的主体、空间、构图、光影、颜色、材质、文字、动作、镜头和限制。颜色应使用可观察的描述和 `HEX #RRGGBB`；不能可靠取样时标记“待确认”，不要凭名称或常识补色。

来自 MP4 的风格结论必须引用至少一个已抽取 PNG 的路径和 `sourceTimeSec`。同一视频在不同候选帧中出现的色调、布光、构图或材质差异，应作为条件性规律或冲突项记录，不得把单一帧的短暂状态写成全片风格。

多资产复刻时，提取跨图稳定锚点、条件性规律与冲突项。稳定锚点进入保留项；只在特定视角、状态或场景出现的规律必须注明触发条件；单张图无法证明的内容只可列为待确认，不得提升为生成规则。

### 3. 生成可执行提示词或计划

提示词须直接写出当前目标的保留项、替换项和每张参考图职责。对复杂图片、关键帧或分镜，优先委派 `image_prompt_specialist`，并交付其所需的已证实事实；对视频目标，优先委派 `video_prompt_specialist`，必要时使用 `pacing_reviewer` 评估时间承载量。specialist 输出缺少最小契约字段时，显式失败，不自行补写平行版本。

图片提示词至少包含：目标画幅、主体身份与位置、环境拓扑、前中后景关系、构图和镜头、光源及方向、颜色与材质、需保留和替换的视觉事实、参考图分工、禁止漂移项。视频提示词还要明确谁先动、动作作用对象、可见结果、镜头运动、屏幕方向和首尾状态。

不要用“完全一模一样”“忠实还原全部细节”替代事实描述。参考图中的水印、品牌标识、受保护人物形象、原始文案和无法验证的隐藏细节必须从提示词中排除或以用户提供的新内容替换。

### 4. 使用资产与画布

在 TapCanvas 上执行时，先确认目标节点和每项前置资产存在真实 URL。引用参考资产前，查询实际绑定；需要补充或更正时按当前资产绑定契约写入完整绑定并再次确认。没有真实上游资产 URL 时，下游生成必须显式失败，不能把文本、连线、占位状态或计划元数据当作资产。

涉及真实 TapCanvas 画布、图像或视频接口时，使用 `tapcanvas-api` 的唯一调用路径。模型候选必须来自当前系统模型目录和实际能力；模型或所需能力缺失时报告具体缺口，不静默切换模型或采用硬编码候选。

对视频或章节分镜续写，读取并引用真实上一组 `tailFrameUrl` 作为下一组首帧参考。缺失时失败；不得以历史文字摘要、计划数据或本地默认画面替代尾帧。

### 5. 交付与修订

生成成功后，保留全部资产 URL、节点结果、工具调用摘要和复刻契约。不要以自动视觉评分阻断、回滚、覆盖或丢弃任何已产出结果。

用户提出修订时，仅修改其指出的契约项及其真实下游依赖。先更新受影响的角色、产品、场景、道具或提示词，再更新依赖的图片、分镜或视频；不要为了修正局部材质而重置无关的构图、身份或已确认资产。

## 特殊对象规则

### 人物与角色

角色复刻前，明确可见的脸部特征、发型、体态、服装、配饰、姿态、道具与当前叙事状态。多镜头任务将这些内容设为连续性锚点，并逐镜记录允许变化。被遮挡的外观、背面、鞋履或道具状态没有参考证据时，要求补充，而不是用默认角色设定填充。

### 产品、物体与材质

区分几何结构、比例、表面材料、反射行为、磨损程度、零部件关系和使用状态。用户需要替换品牌或型号时，保留非品牌化的几何与材质语言，移除或使用用户提供的新标识替换原标识。多视角重建要求覆盖目标所需视图；单视图不能证明的侧面和背面结构必须标为待确认。

### 版式、海报与界面

先锁定画布比例、网格、对齐、留白、视觉层级、文本区、图像区、裁切、分格顺序和阅读路径。只有在用户明确提供新文案后才生成文字内容；否则保留为空白可填充区域或要求文案。不要把低清参考图中的不可读文字臆测为真实内容。

### 视频、分镜和动作

把视频拆为可见镜头事实：时长、景别、机位、镜头运动、主体位置、动作起止、物理结果、音画关系、转场和首尾帧状态。连续镜头需要前一镜真实尾帧和当前镜真实前置资产；任何一个缺失时停止该镜头并报告缺口。音频只在用户提供或明确要求时复刻，不从画面推断对白、音乐或音效。

直接上传的 MP4 若用于风格提取，先执行“MP4 上传预处理”。风格、版式和静态视觉结论只能来自其抽取出的 PNG 与时间码；运动、节奏和转场结论仍须基于视频理解或逐镜证据，不得由单张 PNG 推断。

### 视频形式指纹（节奏与语速）

当复刻目标是“内容形式”而不是单个画面时（用户说“复刻这种视频的形式”“照着这个节奏做”“同款节奏的短剧/漫剧”），先产出形式指纹，它把参考片的节奏变成可照搬的数字：

```bash
node apps/agents/.agents/skills/tapcanvas-film-style-replication/scripts/build-form-profile.mjs \
  --prepare "<prepare-youtube 的 json 输出>" \
  --format markdown
```

- 镜头层：镜头数、剪辑密度（切点/分钟）、镜头时长中位/均值/P25–P75/极值、时长分档分布。
- 文本层：字幕段数、总字数、语速（字/秒）、单段时长与字数中位。仅当 `--prepare` 输入带字幕，或显式传 `--subtitles` 时才产出；未要求字幕时该层为 `null`，不会补造。
- 也能拆开传：`--boundaries <shot-boundaries.json> [--subtitles <segments.json>]`，适合只有单项事实文件的场景。

形式指纹只做聚合，不做检测。镜头边界必须来自 `youtube-storyboard` 的 `prepare-youtube.mjs`（scene 模式），字幕必须来自 `subtitle-transcribe`；脚本不重新解码视频。传 `interval` 模式的输出会被拒绝，因为那条路径没有镜头边界。

把指纹当作复刻契约里的“保留项”目标区间使用。语速依赖源语言与识别粒度，跨语言照搬前先确认来源；不要因为目标是 X 字/秒就改写台词语义去凑数字。

## 失败与禁止事项

以下情形必须原地失败并报告具体原因：关键资产缺失；目标和参考角色不明；交付规格缺失；保留项与替换项冲突；所需文字不可读且未提供；多视图所需角度没有证据；上传 MP4 不是可读取的本地 MP4、FFmpeg 镜头转换检测或抽帧失败、候选 PNG 为空或 PNG 缺少时间码；视频缺少可读取的媒体 URL、尾帧或前置资产；TapCanvas 目标 ID、真实资产 URL 或模型能力缺失；specialist 输出不符合最小契约。

禁止：仅凭文件名或一张模糊图臆测关键细节；把所有参考图当作无差别风格图；在提示词中混入相互冲突的镜头、光源或主体要求；静默默认 route、默认模型、默认提示词或默认资产；以关键词、正则或本地启发式做语义路由；绕过 `tapcanvas-api` 访问真实用户画布；把已生成资产当作失败后可以自动删除的垃圾数据；用未确认资产替换已确认资产。

## 交付前复核

在声明完成前，逐项核对：

- 复刻模式、目标、输出规格和资产角色是否明确。
- 每个保留项、替换项和禁止项是否具备可追溯的证据。
- 参考图职责是否明确，且没有无关参考污染当前目标。
- 多图/多镜头任务的身份、空间、光向、道具和屏幕方向连续性是否有真实依据。
