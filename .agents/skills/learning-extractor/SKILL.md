# AI 错误经验登记

## 概述

这个 skill 用于把 AI 错误从“口头承认”升级为“可追踪记录”。

核心原则：

- 已确认的真实错误默认自动写入，不再等待用户二次确认
- 默认只记录 coding / 实施 / 验证阶段的已确认错误，或用户主动指出且事实已经清楚的错误
- 需求澄清阶段的临时假设、候选方案和口径调整默认不落台账
- 单次事件先记流水，再判断是否升级为模式
- 经验库不记流水账，只记高频、稳定、值得长期防复发的经验
- 某条流水升级为经验后，登记文档中的原记录仍保留，通过模式编号关联，不因升级而删除
- 一旦升级为长期经验，对 AI 后续执行应按强制前置检查处理；除非显式说明“不适用”，否则不得跳过

## 什么时候使用

- 用户说“你刚刚错了”“登记这个错误”“更新错误经验登记”
- 用户明确指出 AI 刚刚的判断、实现、结论或交付物有误，且事实已经清楚
- coding / 实施阶段发现 AI 已提交或准备提交的实现与需求、架构规则、代码事实不一致
- 验证阶段发现自己前面的判断被测试、编译、CI 或运行结果推翻
- 需要判断某次错误是只记流水，还是应升级到经验库

## 什么时候不要使用

- 还没确认这是不是错误，只是在澄清需求
- 需求澄清、方案探索、头脑风暴阶段的临时假设被用户补充或修正
- 用户只是补充需求、改变需求、收窄/扩大范围，或选择了另一个方案
- AI 给出的候选方案、问题选项、设计草案被用户否定，但不存在已确认事实错误
- 只是表达不够清晰，但技术判断本身没有错
- 只是普通开发任务，没有发生错误登记需求

## 阶段边界判断

写入台账前先判断当前处于哪个阶段：

- `澄清 / 探索阶段`：信息尚未冻结，默认不登记。把用户反馈当作需求输入继续收敛，不把正常澄清记录为 AI 错误。
- `设计已确认 / 口径已冻结阶段`：如果 AI 后续回退到旧假设、违背已确认口径或无视用户明确约束，可以登记。
- `coding / 实施 / 验证阶段`：如果 AI 的代码、文档、命令判断、测试结论或交付物被事实推翻，默认登记。

判断口径：

- 需求变化不是错误。
- 偏好选择不是错误。
- 未冻结信息下的合理提问或候选假设不是错误。
- 已冻结事实被忽略、已实现内容出错、验证结论被推翻，才是应登记的错误。

## 记录前先判断

在写入前，先完成以下判断：

1. 这是不是“真实错误”，而不是需求变化
2. 这次错误是单次事件，还是已有模式的再次出现
3. 这次是否已经形成长期防复发资产，例如测试、架构规则、CI、模板约束

如果以上判断还不清楚，不要直接写入经验库。

## 默认执行流程

1. 复述错误现象
2. 归类错误类型
3. 提炼最小证据链：背景、现象与根因、处置与预防
4. 先判断是自动记入登记文档，还是直接升级到经验库
5. 对已确认的真实错误，直接写入 `docs/engineering/learning-extractor.md`
6. 如果满足升级条件，再同步更新 `docs/engineering/ai-error-learnings.md`
7. 如果仍有事实歧义，再说明为什么暂缓写入

## 登记文档写入规则

记录到 `docs/engineering/learning-extractor.md` 时，固定使用 3 个 bullet：

- `背景`：会话主题、错误类型、是否升级、关联模式编号
- `现象与根因`：本次具体错了什么，为什么会错
- `处置与预防`：本次如何修正，后续如何防复发

记录应保持轻量，只保留最小证据链；不要再展开成长段模板。

## 经验库写入规则

记录到 `docs/engineering/ai-error-learnings.md` 时，固定使用 3 行：

- `标题`：`[HE-FL-XXX]` + 一句话规则
- `来源`：首次/最近时间、复发次数、当前护栏
- `教训`：后续执行时必须检查的前置动作

## 升级为经验库的条件

满足以下任一条件时，建议同步更新 `docs/engineering/ai-error-learnings.md`：

- 同类错误已经复发
- 虽然首次出现，但破坏性高、边界稳定、明显值得长期治理
- 本次已经沉淀出长期可复用护栏

## 升级后的处理方式

- 先保留 `docs/engineering/learning-extractor.md` 中的原始事件记录
- 将该条记录在“背景” bullet 中标记为“升级：是”
- 在“背景” bullet 中写入对应的 `HE-FL-XXX`
- 如需控制登记文档长度，可后续做归档，但归档是迁移，不是删除证据链

## 常见错误

- 在事实仍有歧义时过早落账
- 把一次性事件直接写成高频模式
- 只写“错了”，不写根因、影响和预防动作
- 把经验库当成流水账使用

## 快速口令

如果用户说“登记这次 AI 错误”，默认做法是：

1. 先生成草稿
2. 明确说明将写入 ledger 还是直接升级经验库
3. 若事实已清楚，直接落文件；若仍有歧义，再先澄清

## 备注

当前仓库采用“四件套”：

- `AGENTS.md` 负责触发规则
- `docs/engineering/learning-extractor.md` 负责单次事件
- `docs/engineering/ai-error-learnings.md` 负责长期经验
- 本 skill 负责统一执行动作
