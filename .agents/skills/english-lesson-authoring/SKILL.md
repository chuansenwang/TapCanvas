# 英语教学文本创作

把三种输入之一变成一集可直接拍摄、配音的纯英文教学视频脚本：话题、参考视频链接、本地文本文件。

## 交付物

一集脚本 = 固定教学结构（开场独白 → 频道引入 → 场景对话 → 第一人称复述 → 关键句清单 → 订阅片尾）。产物**纯英文**，不出现任何中文：中文译文、生词讲解、教师备注一律不做。

脚本是文档，不是成片。镜头切分、画面描述、时间码属于 `youtube-storyboard` 的职责，本 skill 不产出。

## 输入

三种输入**互斥**，先判定属于哪一种，再走对应分支。判定不是语义猜测：链接是 `http(s)://` 开头，其它输入先看路径是否存在。

| 输入 | 判定 | 处理 |
| --- | --- | --- |
| 话题 | 既不是链接，也不是已存在的文件路径 | 直接进入 D3，按话题选题 |
| 参考视频链接 | `http(s)://` 开头的视频链接 | 下载并取得字幕，然后改写 |
| 本地文本 | 已存在的 `.txt` / `.md` / `.srt` 等文本文件路径 | 直接读取，然后改写 |

无法判定时显式失败，不靠默认分支兜底。

### 参考视频链接

链接输入的下载与字幕识别一律复用现成 skill，不要在本 skill 内重新实现 `yt-dlp` 命令或调用第三方字幕接口。

```bash
# 1. 下载（单条视频，默认不加 --playlist）
uv run python .agents/skills/video-downloader/scripts/download_video.py \
  --title "<video_id>" \
  "<视频链接>"

# 2. 识别字幕（优先复用 YouTube 现成字幕，缺失时本地 Whisper）
python .agents/skills/subtitle-transcribe/scripts/transcribe_subtitles.py \
  --media "<上一步下载的视频路径>" \
  --video-id "<video_id>"
```

改写只消费 `*_transcript.txt` 或 `*_source_subtitles.txt`。下游需要的逐段事实以 `*_transcript_segments.json` 为准，不要从纯文本稿反推时间码。

### 本地文本

直接按 UTF-8 读取。`_source_subtitles.txt` 的 `[mm:ss]` 行首标记在改写前剥除，时间码不进入产物。

## 改写契约

改写是唯一的输入转换动作，三种输入共用同一份契约。

**保留**：教学结构（章节顺序）、话题场景与人物关系、目标句型、语速与句式密度。

**变动**：台词必须重写。不复用参考视频或原文本的句子，只有高频功能短语（`Can I have ...?`、`How much is it?`、`Let's ...`）作为目标句型照常保留。

**不添加**：中文、生词表、语法讲解、教师备注、章节分镜、画面描述。

输入素材信息不足以支撑一集脚本时，显式失败并说明缺什么；不补写假内容，不缩小范围静默交差。

## 选题

仅在话题输入时执行。选题必须先定场景，再定目标句型，两者都落定后再写台词。

优先选自 A1–A2 常见生活场景：点单与购物、问路、面试、看病、旅行、租房、邻里、节庆活动、打电话、预约。

目标句型每集 4–6 个，必须在本集场景里反复复用；同一句型已在上几集用过的，换用新的。

## 角色

固定设定：**两名常驻主角 Mike 和 Kate**，频道 `Mike and Kate's English Channel`，配 2–4 名单集配角。

- **双主角**：Mike 和 Kate 是跨集不变的一对同伴，整季固定，不每集换人或换名。两人都是 A1–A2 学习者的代入对象，在本集都是第一次做这件事。
- **允许单集只有一人出场**：当该集情境里另一人本来就不在场时（例如独自去面试、独自看病、给对方打电话），场景对话只由出场的那名主角与配角推进。缺席的另一人不得凭空出现在场景里，也不要为了凑双人而改写情境。
- **两人之间必须有真实关系**：朋友、同事、室友或家人，由该集场景决定；关系一旦用在某条支线上就保持一致，不中途改名分。
- **两人同场时分工是互相提问**：由一人问、另一人用本集目标句型答，问答来回构成场景对话的主体；两人的问题与回答都要复现当集目标句型。不要让同一个人自问自答，也不要让其中一人退化成纯听众。
- **配角随场景更换**：身份必须来自该场所的真实角色，例如前台、店员、面试官、房东、医生、邻居。配角不跨集复用同一身份，作用是发起需要目标句型才能回应的提问。
- **主角需要有情绪弧线**：开场带着紧张或不确定，结尾放松并有所收获；这条弧线由第一人称独白和复述两段承担，可只由其中一人承担，也可两人各说一半。
- 配角出场要有自然理由：由该场所的真实互动带出，或由「场景真实性」允许的日常小摩擦带出；不要为了加角色而硬塞一句搭话。

## 场景真实性

场景必须是真实生活里会发生的事，不允许虚构。判断标准是：真实的人在这个场合真的会说这些话，且这些话说得出口、用得上。

- 场景要落在真实存在的场所与关系里，例如咖啡店点单、向路人问路、面试等候、房东带看房；不要发明现实里不存在的机构、流程或人物关系。
- 台词要符合真实对话的目的与顺序：说这句话是为了解决什么问题、对方为什么要接这句话。不为了塞句型而说现实生活中不会说的话。
- 允许为了让配角出场而发生一次自然的日常小摩擦：拿错东西、找不到路、排队耽误、东西掉了被旁人提醒。这类摩擦必须在该场所真实常见，且是配角开口说话的自然理由，不承担制造戏剧性的功能。
- 禁止虚构机构和流程，禁止刻意制造戏剧冲突：不写事故、误会升级、身份反转、巧合式相遇，也不写现实里几乎不会发生的极端事件。
- 每个小场景都要能回答一句：这件事在现实里怎么发生？答不上来就换场景，不要靠剧情硬凑。
- 改写已有素材时，如果原素材的对话不符合真实说话方式（例如为了教学效果刻意夸张、语序不自然），按真实说法改写，而不是照着原样保留。

## 难度约束

面向 A1–A2，按下列可检查的规则写，不要用“写简单点”代替判断：

- **句长**：平均句长 3–5 词，单句不超过 12 词。这是主要约束，语速靠短句和回合数拉长。
- **词汇**：只用高频基础词（日常名词、常见动词、常见形容词），超出部分必须换成同义的基础说法。
- **时态**：一般现在时、一般过去时、一般将来时、`can`、`would like`、现在进行时；不出现完成时、虚拟语气、被动语态。
- **规模**：默认 18–26 个场景回合，总词数 700–1000 词，约 6–9 分钟。参考视频实测约 982 词对应 8.9 分钟。
- **每句独立**：一句话只承载一个意思，宁可拆句。

## 教学结构

章节顺序固定为六段，缺任一段视为未完成。

1. **开场独白**：主角用第一人称交代今天要做什么和心情，2–3 句；两人同场时可由一人开场并把另一人带进场景，单主角集则由出场的那人独自开场。
2. **频道引入**：固定三句自我介绍，`Hi, I'm Mike. This is Kate. Welcome to Mike and Kate's English Channel. Here you'll learn real English through everyday conversations. Let's learn real English together.`
3. **场景对话**：主体，18–26 个回合，分小场景，每个小场景至少把当集目标句型各复现一次。
4. **第一人称复述**：主角用过去时复述今天做了什么，3–5 句；两人同场时按 `We ...` 复述或两人各说一句，单主角集用 `I ...` 复述。
5. **关键句清单**：把当集目标句型列成独立句子，6–10 条。
6. **订阅片尾**：`Thanks for watching. Don't forget to like and subscribe. See you in the next lesson.`

## 产物

默认写入独立目录，一次创作一个目录，不把产物与源素材平铺混放：

```text
.scratch/english-lesson-authoring/YYYY-MM-DD-<slug>/
├── script.md            # 主交付：纯英文脚本
├── lesson-package.json  # 结构事实：章节、目标句型、回合数、词数、句长
└── source.json          # 输入来源：类型、路径或链接、video_id
```

`lesson-package.json` 是给下游程序读取的入口，章节以稳定 id 标识；不要在脚本正文里埋机器标记。

发布到视频流水线时，把同一份产物复制到 `Video/` 下该视频的专属目录；两处内容必须一致。

## 自检

完成前逐项核对并如实记录，任一项不过就继续改，不要交差：

- 六段章节是否齐全。
- 目标句型是否 4–6 个，且在场景对话里各自出现至少两次。
- 平均句长是否落在 3–5 词，单句是否都不超过 12 词。
- 总词数与回合数是否落在范围内。
- 产物是否零中文。
- 是否与参考视频存在整句复用。
- 每个场景是否都是真实生活中会发生的场合，且台词符合该场合的真实说话方式。
- 是否 1 名主角 + 2–4 名单集配角；配角身份是否来自真实场所；问答是否由配角发起、主角用目标句型作答。
- 是否出现虚构机构、流程或刻意制造的戏剧冲突。

把结果写进 `lesson-package.json`，并附上实际计算出的句长、词数与未通过项。
